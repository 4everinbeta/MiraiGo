# Phase 06 Plan 01: Harden destination and timeline extraction behavior

## Objective

Make destination and timeline extraction deterministic and clarification-safe for natural-language queries containing mixed route/date phrases.

## Must-Have Truths

1. Route phrasing (`from ORIGIN to DESTINATION`) does not get misclassified as timeline date range.
2. Timeline date windows are recognized when phrases contain date-like terms, including common natural language forms.
3. Destination extraction avoids date/timeline tokens and maintains confidence/ambiguity semantics needed by clarification.
4. Existing API contract keys (`location`, `date_range`, `normalized_timeline`, `slot_metadata`) remain backward compatible.

## Tasks

1. Add/extend RED tests for timeline-vs-route and destination false-positive cases.
2. Refactor `extract_intent` destination/timeline parsing into explicit, ordered helper steps.
3. Recalibrate confidence/ambiguity for destination and timeline slot metadata when parse quality is uncertain.
4. Ensure clarification sequencing still behaves correctly by running service clarification tests.

## Verification Commands

- `PYTHONPATH=. pytest src/tests/nlp/test_intent.py src/tests/nlp/test_intent_date_range.py src/tests/nlp/test_intent_confidence.py -q`
- `PYTHONPATH=. pytest src/tests/services/test_clarification_loop.py -q`
- `PYTHONPATH=. pytest src/tests/api/test_search.py -q`

## Success Criteria

- All above tests pass.
- New edge-case tests prevent regression on route/date ambiguity.
- Clarification loop still selects next question consistently from slot metadata.
